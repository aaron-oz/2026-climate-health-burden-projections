2. Check disk space. In the Colombia sample from the test, a Workflow B file was about 1.2 times the size of the matching burden file, so the output will take roughly 1.2 times the space of your ssp370 and ssp585 burden files:

3. Run the scaling. For every location this scales ssp370 and ssp585 against ssp245 for all years, and also scales ssp245 against itself for 2022 and 2050 as a check (it must reproduce the unscaled ssp245 exactly). Your test run took 3.7 seconds per combo, and this is about 310,000 combos, so roughly 320 CPU-hours in total. At 40 at once that is about 8 hours if it scales evenly, which I haven't verified. Set -j to whatever your machine handles comfortably.

```
. ./run_env.sh
mkdir -p output/logs/wb_full
parallel -j 40 --joblog output/logs/wb_full/joblog.tsv \
  "Rscript global-scripts/util_apply_workflow_b_batch.R --location_id={} --ref_scenario=ssp245 --target_scenarios=ssp370,ssp585 --years=2022-2050 > output/logs/wb_full/loc_{}.log 2>&1 && \
   Rscript global-scripts/util_apply_workflow_b_batch.R --location_id={} --ref_scenario=ssp245 --target_scenarios=ssp245 --years=2022,2050 > output/logs/wb_full/loc_{}_ref.log 2>&1" \
  ::: $(Rscript -e 'cat(readRDS("output/intermediate/ihme_loc_map.rds")$loc_id)')
```

Each location's log ends with a line like "Done: N ok, N skip, N fail, N missing-ref". Expect "missing-ref" only for the models with no ssp245 run: taiesm1 for ssp370, and taiesm1 and hadgem3-gc31-mm for ssp585. Any "fail" is worth a look. This prints the last line for every location:

```
for f in output/logs/wb_full/loc_*.log; do echo "$f: $(tail -1 $f)"; done
```
